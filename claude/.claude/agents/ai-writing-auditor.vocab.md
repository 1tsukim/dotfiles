# AI 臭検出語彙集 (ビジネス資料向け)

`ai-writing-auditor` agent が監査時に参照する語彙データベース。
追加・削除は **該当 Tier の表に行追加するだけ** で済むよう設計しています。

## 使い方

- agent は監査開始時にこのファイルを Read して、表の単語をパターンとして使う
- 「単語」列の表記が出現したら、「修正方針」列のルールで書き換え候補を作る
- 「備考」列に文脈条件 (技術文脈は許容など) を書けば、agent はその条件で除外できる

## 重大度の見方

- **P0**: 信頼を損なう (根拠不明数値、過剰主張、チャットボット痕跡)
- **P1**: 明らかな AI 臭 (Tier1 語彙、テンプレ言い回し)
- **P2**: 磨き (Tier2/3 密度警告、構造の癖、文末の癖)

## Tier 2 — クラスタで警告 (同段落に 2 つ以上で発火 / P2)

単独では許容範囲だが、複数並ぶと AI 臭が増す語。

| 単語 | 修正方針 | 備考 |
|---|---|---|
| 推進する | 「進める」「実行する」 | 過剰使用時 |
| 加速する | 「早める」 | 過剰使用時 |
| 取り組む | 具体的な行動を書く | 具体性なしの使用 |
| 価値提供 | 何の価値かを書く | |
| 価値創出 | 何の価値かを書く | |
| 持続可能 | 「続けられる」 | |
| 持続的 | 「継続的に」または削除 | |
| 抜本的 | 「根本的」 | |
| 包括的 | 「すべて含む」 | |
| 多角的 | 「複数の視点で」 | |
| ダイナミック | 「動的」または削除 | |
| ロバスト | 「堅牢」 | 技術文脈は許容 (ML の robust loss 等) |
| スマート (〇〇) | 削除または具体化 | |
| インテリジェント | 「賢い」または削除 | |
| バリュー | 「価値」「強み」 | |
| フェーズ | 「段階」 | |
| スケール | 「拡大」「規模拡張」 | 動詞使用時 |
| スケーラブル | 「拡張可能」 | |
| トランスフォーメーション | 「変革」または具体化 | |
| 急増 | 「増加」「増えた」へ。具体的な数値や倍率を添える | **主観評価が入る**。事実ベースで書きたい時は中立語へ。意図的に強調したい時のみ許容 |

### 主観評価が入る語 (事実ベースの語に置き換える)

ニュートラルでなく書き手の意思が入る語。基本は中立的な表現に置き換え、強調したい意図がある時のみ使う。

| 単語 | 中立な言い換え | 備考 |
|---|---|---|
| 急増 | 増加 / N% 増えた | 意図的な強調以外は避ける |
| 急減 / 激減 | 減少 / N% 減った | 同上 |
| 大幅に | N% / 具体的な数値 | 「大幅」は主観。数値を添える |
| 劇的に | 具体的な数値 | 同上 |
| 飛躍的に | 具体的な数値 | 同上 |
| 驚くべき | 削除 + 数値 | 「驚き」は書き手の感情 |
| ぐっと / グッと | 削除 / 具体化 | カジュアル主観 |
| 顕著に | 「目に見えて」+ 数値 | |
| 散発 | 件数で示す / 削除 | 件数が併記されていれば冗長 (例:「1〜5件の散発」→「1〜5件」) |

## Tier 3 — 密度で警告 (3% 超で発火 / P2)

接尾辞パターン。1 語ずつでは問題なくても、密度が高いと文章全体が浮く。

| パターン | 例 | 修正方針 |
|---|---|---|
| 「〜性」 | 効率性 / 柔軟性 / 機動性 / 拡張性 / 可能性 / 戦略性 / 実効性 | 名詞化「効率」「柔軟さ」 |
| 「〜化」 | 最適化 / 自動化 / 効率化 / 標準化 / 可視化 / 業務効率化 / 高度化 | 動詞へ「最適にする」 |
| 「〜的」 | 戦略的 / 抜本的 / 効果的 / 革新的 / 多角的 / 包括的 / 本質的 | 削除または具体化 |
| 凡庸な強調 | 重要な / 大切な / 素晴らしい / 注目すべき | 削除または具体的な根拠を添える |

## Claude 出力構造の癖 (P1/P2)

ai-writing-auditor の **主用途** に対応するセクション。Claude (Code) が生成した文章を浄化するときに参照する。

| 癖 | 例 | 修正方針 |
|---|---|---|
| 結論宣言テンプレ | 「結論から書きます」「まず〜から確認します」 | 削除、本題へ |
| メタ謝罪 | 「正直に言うと」「率直に書きます」「ちゃんと検証してませんでした」 | メタ言及は減らし、内容で示す |
| 数列宣言 | 「3 つあります」「2 つの観点で」 | 散文展開、必要時のみ箇条書き |
| 対比過剰 | 「ただし」「とはいえ」「一方で」を 1 段落に複数 | 1 段落に 1 つまで |
| まとめセクション必置 | 「## 結論」「## 総括」「## 次に取れる動き」 | 不要なら削除 |
| 過剰な表組み | 比較対象が 2-3 件しかないのに表化 | 散文 1-2 文で済むなら表にしない |
| ボールド乱用 | 重要そうな単語を片っ端から **bold** | セクションあたり 1 つまで |
| 同意確認テンプレ | 「やります」「進めます」「やりましょう」 | 不要なら削除、本題に直接入る |
| 手順の自動箇条書き化 | 不要場面でも「1. ... 2. ... 3. ...」 | 文章で書けるものは文章で |
| 質問オープン化テンプレ | 「どれから着手しますか?」「実行しますか?」必置 | 既に文脈で明示済みなら削除 |

## フォーマットパターン

| パターン | 修正方針 |
|---|---|
| em dash (—) | 0 を目標。1,000 語あたり 1 つが上限 |
| Bold 過多 | セクションあたり 1 つまで |
| ヘッダ絵文字 | 削除 (Slack のみ末尾 1-2 個許容) |
| 過剰箇条書き | 散文へ。本当にリスト的内容のみ残す |

## 文構造パターン

| パターン | 修正方針 |
|---|---|
| 「〜ではなく、〜だ」 | 直接肯定文へ |
| 空虚な強調語 (言わずもがな / まさに) | 削除 |
| 過剰なヘッジ (おそらく / もしかしたら / いちおう) | 削除 |
| 3 つ並列の癖 | 多様化、1 ピースに 1 つまで |
| 段落間に bridge 文がない | 文脈を繋ぐ 1 文を追加 |

## 文末の癖

| パターン | 修正方針 |
|---|---|
| 〜と思います | 削除または「〜です」 |
| 〜していきます / 〜していきましょう | 「〜します」 |
| 〜できます (中立的能力提示で機能していない) | 動詞へ直接 |

## 追加・編集のガイド

- 単語を増やすときは該当 Tier の表に行追加するだけ
- 文脈で許容したい場合は「備考」に書いておく (技術文脈、特定ドメイン等)
- ビジネス資料以外のプロファイル (スライド / README / コミットメッセージ等) で許容したい場合も備考に記載
- 新カテゴリが必要なら H2/H3 セクションを足す
- Tier の昇格・降格は表の行を別 Tier セクションへ移動
