# 失敗時のルール昇格提案（自主規制）

タスクが失敗・誤結果・ユーザー訂正を受けた時、汎用的な失敗パターンであれば
`~/.claude/rules/` への追加を **ユーザーに提案** する（自発追加しない）。

## 手順

1. **分析**: 根本原因を 1〜2 文で特定してユーザーに伝える
2. **閾値判定**: 以下のいずれかを満たすときのみ提案へ進む
   - 同一セッション内で **2 回以上**同種失敗が出た
   - 会話／memory に同種失敗の痕跡があり、再発リスクが高い
   - パターンが汎用的（特定リポ・特定タスク限定でない）
3. **提案**: 「このパターンを `~/.claude/rules/<file>.md` に追加しますか」と一文で確認
4. **承認後のみ実行**: ユーザーが「入れて」「ルール化して」等と明示したときだけ
   既存ファイルへ追記、または新規ファイルを作成する
5. **index 更新**: 新規ファイル作成時の `~/.claude/CLAUDE.md` への参照追加も
   別途ユーザーに承認を取ってから行う

## 記録する

- 誤った前提に基づく失敗
- ツール／API／言語機能の誤用（macOS BSD `find` と GNU `find` の差異など）
- 環境特有の落とし穴（`sed -i ''`、`date` のオプション差、`readlink -f` 非対応 等）

## 記録しない

- 一回限りの typo・うっかり
- 外部システム障害（API rate limit、ネットワーク断）が原因の失敗
- ユーザー個人の好み・嗜好 → こちらは memory 側で扱う

## 既存 skill との分担

- `improving-skills-and-rules` skill: **ユーザー発**の昇格（「これルール化して」と言われた時）
- 本ルール: **Claude 発**の昇格提案（自分が失敗した時の自己申告）
- いずれもユーザー承認を経てから `~/.claude/` 配下を書き換える

なぜ重要か: 失敗を Claude が自発判断で rules に書き込むと、
`do-not-self-modify-claude-config.md`「明示指示があった時だけ `~/.claude/` を改変」と矛盾し、
防御層を自分で剥がす結果になる。**提案にとどめ承認を経る** のが安全装置。
